# 云服务器部署（Docker，告别本机 MySQL 折腾）

在云上跑时，**MySQL、后端、前端**都由 Docker Compose 一起拉起，数据库用容器里的 **3306**，不再依赖你笔记本上的 MySQL 安装。

## 一、你需要准备

| 项目 | 说明 |
|------|------|
| 云服务器 | 阿里云 / 腾讯云 / 华为云等 **Linux** 机型，建议 **2 核 4G**，系统 **Ubuntu 22.04** 或 **Debian 12** |
| 网络 | 安全组 / 防火墙放行 **TCP 80**（网站入口）。可选放行 **8080** 方便直接调 API |
| 代码 | 把整个 **`bg` 项目文件夹** 上传到服务器，或用 `git clone` |

## 二、安全组（必做）

在云控制台找到该实例的 **安全组规则**，入方向增加：

- **端口 80**，来源 `0.0.0.0/0`（或你的办公网 IP 更安全）  
- （可选）**端口 8080**，同上  

不开放 80，浏览器访问不了页面。

## 三、登录服务器并安装 Docker（Ubuntu 示例）

SSH 登录（把 `你的服务器IP` 换成公网 IP）：

```bash
ssh root@你的服务器IP
```

安装 Docker 与 Compose 插件：

```bash
apt-get update
apt-get install -y ca-certificates curl
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

验证：

```bash
docker --version
docker compose version
```

（若你更熟 **一键脚本**：也可使用官网 `get.docker.com`，再单独安装 `docker-compose-plugin`。）

## 四、上传项目

**方式 A：Git（推荐）**  
把代码推到 Gitee/GitHub，在服务器上：

```bash
cd /opt
git clone <你的仓库地址> finresearch
cd finresearch/bg   # 以仓库根目录下 bg 为准，按你实际路径进入含 docker-compose.yml 的目录
```

**方式 B：本机 ZIP**  
在 Windows 上把 **`bg` 文件夹**打成 zip，用 **WinSCP / 宝塔** 传到服务器 `/opt/`，再：

```bash
cd /opt/bg
```

确保当前目录能看到 **`docker-compose.yml`**。

## 五、配置环境变量（至少改 JWT）

```bash
cd /opt/bg   # 按你的实际路径
nano .env
```

写入（**把 JWT_SECRET 换成一长串随机字符**）：

```env
JWT_SECRET=这里换成至少32位随机字符串不要用默认值
ANTHROPIC_API_KEY=
```

保存退出。没有 `.env` 也能启动，但生产环境**必须**改 `JWT_SECRET`。

> 说明：`docker-compose.yml` 里容器内 MySQL 已固定为 `root/root` 且仅 **Docker 内网**可访问，不暴露给公网；仅作 MVP 演示。正式对外服务请改强密码并限制访问。

## 六、一键启动

在包含 **`docker-compose.yml`** 的目录执行：

```bash
docker compose up -d --build
```

首次构建约 3～10 分钟（拉镜像 + Maven 打包）。查看状态：

```bash
docker compose ps
docker compose logs -f backend
```

看到日志里有 **`Started FinResearchApplication`** 即后端正常。

## 七、访问

- **网站（前端 + 反代 API）**：`http://你的公网IP`  
- **Swagger**：`http://你的公网IP/swagger-ui/index.html`  
- **直连后端（若安全组开了 8080）**：`http://你的公网IP:8080/swagger-ui/index.html`  

默认演示账号：**demo / demo123456**（首次启动由程序自动创建）。

## 八、常用运维命令

```bash
# 停止
docker compose down

# 重启
docker compose up -d

# 看日志
docker compose logs -f backend

# 备份数据库
docker compose exec mysql mysqldump -uroot -proot finresearch > backup.sql
```

## 九、和本机开发的区别

| 本机 | 云上 Docker |
|------|-------------|
| 要自己装 MySQL、改端口密码 | Compose 里自带 MySQL，后端用服务名 `mysql` 连接 |
| 前端 `npm run dev` | **不用**在服务器跑 `npm dev`；浏览器直接访问 **80 端口** 的 Nginx 静态页 |
| 易端口冲突 8080 | 只保证云安全组放行即可 |

---

若 `docker compose up` 报错，把 **`docker compose logs backend` 最后 50 行**复制下来即可继续排查。
